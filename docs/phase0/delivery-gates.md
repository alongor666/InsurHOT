# 项目接管与交付门槛

状态：2026-09-29 接管提议；原稿 PR #1 HEAD 3d838a4 未通过实施基线验收。Codex 已获用户“评审与验收，然后接手项目”的授权，承担本会话内的评审、整改准备和交付管理；这不是后台常驻服务或已派出其他 Agent。

## 1. 权责与工作方式

- Owner：产品使命、核心边界与重大资源承诺的最终决策者。C0 沿用已确认版本。
- Codex：维护项目台账、依赖、验收标准与证据；执行可逆的仓库工作，发现阻断项先处置，不把实现细节交回 owner。
- 实现者：按任务卡交付固定 HEAD、变更说明、测试命令和结果、风险与回滚办法。未实际启动的执行者一律写“未派工”，不得写进行中。
- 评审者：必须独立于本次变更的撰写过程；同一账号不等于独立评审，同一作者换措辞也不是独立评审。Codex 可以评原稿，Codex 新写的修订需另一独立执行者复审。
- 采购、付费模型调用、律所聘用、生产发布或外部业务承诺在具体对象/费用/范围明确后另走授权；当前均未执行。不开启绕过限流、登录墙或权限检查的采集。
- 单一任务分支、单一写入者；先核查现有 PR 与 HEAD，避免与原作者同时写同一分支。进展以仓库证据为准，不承诺无人值守持续推进。

## 2. 三道门

| 门 | 通过条件 | 不要求提前完成 |
|---|---|---|
| G0 文档合并 | 最新 HEAD 的独立实质评审；IH-R01–05 无未关闭项；P2已修或明确承接；本地引用/章节/差异检查；GitGuardian等现有检查成功；非Draft | 不要求 Node 构建、数据库、Docker、律师报告或58案例全部核完 |
| G1 Phase 0 实施基线验收 | G0满足；原稿与修订一起成为基线；首个任务及范围已冻结；ADR逐项记录接受/推迟/待决及权限，未获批准者仍 Proposed；研究事实/候选/假设分离；未决项有责任角色和阻断点 | 不要求MVP实现、线上30天指标；不把文档合并当全部ADR通过 |
| G2 Phase 1 上线 | 固定实施HEAD的CI及独立评审；安全/预算/许可/公开出口测试；金标及影子运行达标；适用的品牌、数据、发布法律边界已核准；有运维/更正/撤回责任人 | 不用“后续补证据”放行无依据事实 |

规格 §31.3 的运行30天指标属于 G2 上线后的持续验收；上线前用锁定评测集和影子运行检查相同质量目标，生产观察期结束再作最终运营验收。时间计划从前置条件满足后计算，不固定承诺12周。

## 4. T1 可直接执行的验收合同

1. `UPSTREAM.md` 固定仓库、完整SHA、LICENSE/NOTICE、引入范围。先保留可运行基线，再分提交改安全默认、品牌和可选模块；保留许可证中的原名，不作全仓字符串清空。
2. 默认无采集、无模型、无推送、无IndexNow。测试分别覆盖未设置、false、明确true；只用本地假服务验证可启用路径，未批准的外部调用为零。
3. 缺预算/无价格/金额耗尽时拒绝付费；并发预留原子化；未知回执保留费用预留；所有升级/降级服从全局及任务预算。预算值未获批准时保持零，不自行填运营预算。
4. package lock 固定依赖；typecheck、web build/test、PG临时库 migrate/seed/backend test、Docker smoke都有对应HEAD结果。严禁连接生产数据库；临时库以 `_test` / `_ci` 结尾。
5. 记录被移除leaderboard/monitor的路径及路由/队列行为，无悬空导入；公开品牌替换与许可证保留分别验证。
6. 交付可复现命令、结果与失败日志摘要；完整CI未跑过就保留Draft。导入只是工程基线，不代表InsurHOT产品已上线。

## 5. ADR 与未决项

ADR-023 是已有 owner 确认；ADR-000–022 不批量改 Accepted。T0复审负责文档可实施性；T1启动前应将基线导入、默认安全、许可保留的技术裁决正式记账。会影响品牌/独立性/费用/公开形态的决策仍按其权限处理。

| 未决项 | 责任角色 | 阻断点 | 期间允许的工作 |
|---|---|---|---|
| 修订独立复审 | 非修订作者；执行者未派工 | G0/G1 | 本地文档核查与任务准备 |
| 运营预算与模型用途 | Owner裁定；Codex准备估算 | 首次真实付费调用 | 零外部调用的测试、规则处理 |
