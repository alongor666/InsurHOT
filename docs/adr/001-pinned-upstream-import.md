# ADR-001：固定上游一次性导入

状态：Accepted（2026-09-30，Codex依据owner“接手项目、制定行动规划、启动开发流程”的授权作可逆技术裁决）。仅本技术决策被接受，不批量改变其他Proposed ADR。

决策：使用 `KKKKhazix/AIHOT@589f79eff09470b31ba8a7f1d9eb62d36ff2be6c`，不追随上游HEAD，不导入上游历史；经489文件清单校验后先隔离暂存，再单独PR整合应用。上游当前HEAD不同不构成自动升级理由。

依据：Phase0已验收的审计、安全缺口及交付门槛。根LICENSE为MIT；NOTICE明确品牌/Logo不随代码授权、第三方材料各有条款。保留根LICENSE、NOTICE和资产目录内所有第三方许可；不对许可文本做品牌替换。

引入范围：M0.1仅导入清单和工具，无应用代码；M0.2拟引入固定快照中的应用、包、行业配置、数据库、测试、部署及依赖锁。根README/AGENTS/CLAUDE与本仓文档冲突时保留本仓工作规则，将上游原件归档到docs/upstream/；实际逐路径映射在M0.2的UPSTREAM.md中记录。上游工作流须审查后启用，不能直接启用生产部署。

安全约束：快照导出不运行npm、hook、worker或数据库命令。导入不代表上游默认安全；缺省模型/采集、缺预算放行由M0.3实际修正。在此之前禁止启动带真实凭据的服务。

最强反方：直接重写可避免无关模块和品牌清理成本。当前优先复用经审计的公共读取层、任务/回执及测试结构；若导入后依赖/安全改造成本高于窄重写，记录证据并重新评估，而不是固守80%复用估算。

验证：完整SHA与清单逐项一致、许可证字节保真、二进制无损、模式保留、禁止覆写与路径逃逸。后续typecheck、数据库及Docker属于应用验收，不由本ADR替代。
